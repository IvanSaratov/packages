# packages

Личный публичный репозиторий пакетов: [сайт и инструкция подключения](https://ivansaratov.github.io/packages/).

Сейчас поддерживается **Fedora 44 x86_64**, пакет **finances**.

## Установка и обновление

Скачайте [ivansaratov-fedora.repo](https://ivansaratov.github.io/packages/ivansaratov-fedora.repo),
проверьте содержимое и установите в /etc/yum.repos.d/. После этого:

~~~sh
sudo dnf install finances
sudo dnf upgrade
~~~

Открытый ключ: [RPM-GPG-KEY-finances](https://ivansaratov.github.io/packages/keys/RPM-GPG-KEY-finances).

Отпечаток: **596868911C1A853E42B542B6E9FDF6D61C3EE740**.

При импорте ключа сверьте отпечаток. Для подключения репозитория на клиенте не нужны GitHub-токен или локальное зеркало.
Проверка подписей RPM включена. Индекс передаётся по HTTPS без отдельной GPG-подписи.
База данных и служба Finances настраиваются администратором отдельно.

## Публикация

В Releases хранятся подписанные RPM. На Pages публикуются только RPM-MD, открытые ключи,
.repo и страница инструкции. Исходные проекты и закрытые ключи хранятся отдельно.

Workflow .github/workflows/static.yml запускается при изменении main, публикации релиза
или вручную. Он проверяет все разрешённые стабильные неизменяемые релизы, создаёт общий
индекс всех версий и проверяет его настоящим клиентом DNF перед публикацией.
Неудачная сборка сохраняет предыдущий сайт. Хешированные файлы старых метаданных
сохраняются на 48 часов с момента последнего использования текущим индексом.

Для пакетов используется тег PACKAGE-vVERSION-RELEASE, например finances-v0.1.1-1.fc44,
и имя RPM PACKAGE-VERSION-RELEASE.ARCH.rpm. Файлы релиза должны иметь GitHub SHA256 digest.
Подписи проверяются в отдельном rpmdb только ключом, разрешённым для конкретного пакета.
Ключи из вложений релиза не используются как источник доверия.

Чтобы добавить другой проект, внесите имя пакета, ожидаемый epoch, открытый ключ и его
отпечаток в repository.json. При необходимости добавьте платформу в targets.
Сборщик включает архитектуры согласно targets и noarch. Нужен хотя бы один разрешённый
пакет для каждой платформы; неподдерживаемые Fedora-релизы не индексируются.
Версии и сборки должны помещаться в безопасное Git-имя тега (буквы, цифры, точки, _, +, -).

## Проверка разработки

~~~sh
docker build -t rpm-repository-tools tools
docker run --rm --network none \
  --mount "type=bind,source=$PWD,target=/source,readonly" \
  rpm-repository-tools python3 -m unittest discover -s tests -v
~~~

Тесты создают собственные временные ключи и синтетические RPM внутри контейнера.
Производственный закрытый ключ подписи тестам и сборщику индекса не нужен.
